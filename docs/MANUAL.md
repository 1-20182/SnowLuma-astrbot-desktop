# 操作手册（SnowLuma × AstrBot 联合控制台）

> 写给"不想碰命令行"的人。照着做就行，每一步都写了**点哪里、看到什么、出问题怎么办**。
> 版本：见顶栏 `v…`；本手册随程序一起更新（`docs/MANUAL.md`）。

---

## 0. 三十秒认识这个软件

它把两个开源项目打包成一个能点着用的桌面程序：

| 组件 | 干什么 |
| --- | --- |
| **SnowLuma** | QQ 协议端：把你已登录的 QQ 接管过来，转成 OneBot 接口 |
| **AstrBot** | 大模型机器人框架：收消息 → 问大模型 → 回消息，还能装插件 |
| **本控制台** | 负责装、配、启停、连通、排错、升级，全程图形化 |

三个服务的默认端口：控制台 **8790** / AstrBot 面板 **6185** / SnowLuma 面板 **5099** / OneBot **6199**。

## 1. 安装与第一次启动

**Windows**

1. 解压 `SnowLuma-Desktop-v…-win-x64.zip`（**只解压，别在压缩包里直接双击**）
2. 双击 `SnowLuma-Desktop.exe`

**Linux**（x64；首次请先过一遍 [LINUX.md](LINUX.md)）

1. 解压 `SnowLuma-AstrBot-Console-v…-linux-x64.tar.gz` 或 `git clone` 本仓库
2. 在项目目录**运行启动脚本** `./一键启动.sh`（等价 `.venv/bin/python3 -m slab serve`）
3. 浏览器打开 <http://127.0.0.1:8790>

**接着（两个平台一样）**——首次会弹**四步向导**：

| 步骤 | 你要做的 | 判断成功的标志 |
| --- | --- | --- |
| ① 环境检查 | 一般无需操作，看有没有红项（Linux 会多出 ptrace/setcap/DISPLAY 三项） | Python / Git 是绿勾；端口空闲 |
| ② 安装项目 | 点两次安装（SnowLuma 约 40 MB / AstrBot 依赖 200 MB） | 两张卡都变「已安装」 |
| ③ 填写配置 | 机器人 QQ 号（**小号**）、管理员 QQ（你自己）、大模型 Key | 点「保存设置」有绿色提示 |
| ④ 启动 | 点「启动」 | 状态灯变绿，日志出现 `session started` |

> 想跳过向导：右上角「跳过」。想看回来：清掉用户数据或换一个解压目录。

**第一次启动为什么慢？** 要解压 + 过一遍杀毒软件（Linux 上是首次建 venv / 装依赖），通常 5~15 秒；
之后 2~5 秒。启动页有秒表和轮播提示，不是卡死。

## 2. 窗口怎么操作（重点：**关闭是长按**）

本程序没有传统标题栏，顶栏就是标题栏（可以按住拖动窗口）。右上角三个按钮：

| 按钮 | 图标 | 怎么用 | 效果 |
| --- | --- | --- | --- |
| 最小化 | `—` | 单击 | 收进任务栏，服务继续跑 |
| 最大化 / 还原 | `▢` | 单击 | 全屏 / 还原；**双击顶栏空白**同样效果 |
| 置顶 | `◎` | 单击 | 窗口永远在最前；再点取消 |
| **电源键** | `⏻` | **按住不放约 1 秒**（外圈进度环画满才松手） | 弹出「要收起还是退出？」 |

电源键弹窗里只有两个选择：

- **收起窗口** —— 服务继续跑，机器人不掉线（推荐日常这么用）
- **彻底退出** —— 停 SnowLuma / AstrBot 并结束所有进程、释放端口

其它退出方式（效果同「彻底退出」）：

- 快捷键 `Ctrl+Q` → 弹出同一个电源菜单
- `Alt+F4` / 系统关闭 → 会先停服务再关窗，不留后台进程

> **为什么必须长按**：机器人挂机时点一下就没了太危险。按下 1 秒 + 二次确认才生效；
> 而且就算某一步卡住，程序也会在 **9 秒内强制退出**（不会出现"服务停了窗口还在"）。

## 3. 登录机器人 QQ

### 3.1 先搞清楚一件事

**SnowLuma 不会弹二维码。** 它的原理是注入到**已经登录的 QQ 进程**里，把会话转成 OneBot。
所以"扫码"是在 **QQ 客户端**里扫，不是在控制台里扫。

### 3.2 方式 A：用本机已登录的 QQ（最简单）

1. 电脑版 QQ（NT 版 9.9+）里登录**机器人小号**
2. 控制台「运行」页 → 启动 SnowLuma
3. 「运行 → 接入 QQ」列出正在运行的 QQ 进程 → 找到小号那个 → 点 **「用这个」**
4. 日志出现 `[Hook] login detected` → `[OneBot] session started` 就成功了

> 控制台默认是**手动注入**（不会自动接管你日常用的 QQ）。
> 注入后还会**回读账号**：万一注入到你的主号，会自动解除并提示。

### 3.3 方式 B：软件内隔离一个 QQ（更安全）

**Windows**：「运行 → 隔离启动 QQ」会打开一个**独立数据目录**的 QQ 窗口：
`<存储盘>\SnowLumaAstrBot\qq\clones\bot\`，在里面登录小号，再回控制台「刷新进程 → 用这个」。

隔离做了：独立 `APPDATA/LOCALAPPDATA/TEMP` + 独立 `--user-data-dir` + 注入 sandbox DLL 给互斥体改名（允许第二个 QQ 实例）。

**Linux**：没有 DLL 注入这回事（那里靠 ptrace），等价做法是**独立 HOME 多开**：
「运行 → 接入 QQ」→「独立 HOME 多开」会用一个干净的 `HOME` 启动 `/opt/QQ/qq`，
分身目录默认在 `<存储根>/qq/clones/<名称>/home`（存储根默认 `~/.local/share/SnowLumaAstrBot`）。
先按 [LINUX.md](LINUX.md) §5 装官方 Linux QQ，扫完码再「刷新进程 → 用这个」。
手工等价命令：

```bash
HOME=~/qq-bot-home XDG_CONFIG_HOME=~/qq-bot-home/.config /opt/QQ/qq --no-sandbox &
```

> 已知边界（Windows）：QQ 的账号列表可能存在 `ProgramData`/注册表，仍然共享；彻底隔离需要注册表重定向（尚未默认开启）。
> Linux 上同理，隔离的是 `$HOME` 下的数据，登录态本身仍按账号走。

### 3.4 登录不上 / 检测不到？

| 现象 | 处理 |
| --- | --- |
| 列表里没有 QQ 进程 | 先登录 QQ 客户端再刷新；确认是 NT 版（Linux：官方 `/opt/QQ`） |
| 提示"注入失败" | SnowLuma 没启动，或面板密码不对（见第 6 节）；Linux 上看第 3.4 节最后两行 |
| 日志没有 `login detected` | 权限不一致：QQ 与 SnowLuma 必须同一个 Windows 用户（Linux：**同一个 uid**，两边都别用 sudo） |
| 只弹旧窗口 | 先退出你自己在用的 QQ，再点「隔离启动 QQ」（Linux：「独立 HOME 多开」） |
| 账号被风控 | 新号 / 异地登录常触发，先在手机 QQ 完成验证 |
| Linux：日志里有 `EPERM` / 注入不动 | 缺 `sudo setcap cap_sys_ptrace=ep <node 真实路径>`，或 `ptrace_scope=3`；见 [LINUX.md](LINUX.md) §4 |
| Linux：QQ 起不来 / 没有二维码窗口 | 无图形会话（`DISPLAY` 为空）；见 [LINUX.md](LINUX.md) §7 |

## 4. 配置页逐项说明

按页面从上到下：

1. **端口**：控制台 8790 / AstrBot 6185 / SnowLuma 5099 / OneBot 6199 —— 四个不能撞车
   有「检查并自动换端口」按钮，一键避让。
2. **QQ 账号**
   - `QQ 号`：**机器人小号**
   - `管理员 QQ`：你自己（主号），才能用 `/help`、`/reset` 等管理指令
   - 「**读取已登录账号**」：直接从 SnowLuma 读真实登录号写回（多账号时自动避开管理员主号）
3. **大模型**
   - `Base URL`：如 `https://api.deepseek.com/v1`，也可以是你自己的本地网关（如 `http://127.0.0.1:7864/v1`）
   - `API Key`：填完点 **「拉取可用模型」** → 从下拉里挑模型（不用手敲）
   - **「测试大模型连接」**：真发一次 1 token 请求，直接告诉你 `401 Key 无效` / `连不上` / `超时` / `额度不足`
   - **「从 AstrBot 读回」**：如果你直接改过 AstrBot 配置，用它把真实生效的地址/模型/Key 同步回控制台
4. **触发规则**：私聊是否必答、群里要不要 @ 或前缀
5. **安装位置与备份**：显示存储规划（默认**不落 C 盘**）、导出/导入整份配置、QQ 注入模式（手动 / 自动）
6. **维护**：日志 / 安装包保留天数、立即清理、清理残留进程、升级控制台

改完点右下角 **「保存设置」**。

## 5. 联动：让消息真正跑通（关键）

「联调」页 → **写入联动配置** → 「运行」页 **一键启动全部** → 联调页看四块状态。

### 5.1 两种模式，推荐「中继（bridge）」

| 模式 | 链路 | 说明 |
| --- | --- | --- |
| native（直连） | SnowLuma → AstrBot | 少一跳，但 AstrBot 的 aiocqhttp 在重连时容易把"能发消息的 bot"登记搞丢 → **能收不能发** |
| **bridge（中继，推荐）** | SnowLuma ⇄ 内置中继 ⇄ AstrBot | 中继是全双工客户端，**私聊/群聊/图片/文件/@ 全部支持**，插件动作也能透传 |

切换方法：配置页 `联动模式` 选「中继」；或联调页点 **「修复发送链路」**（自动切到中继并验证）。

### 5.2 什么时候用「双向自检」

机器人不回话、群聊没反应、插件不动 —— 先点它。四步逐条给结果：

```
✓ SnowLuma → AstrBot 连接   self_id=… clients=1
✓ AstrBot 面板登录           已拿到 token
✓ AstrBot API Key（im 权限） abk_…
✓ AstrBot → SnowLuma → QQ   发的是一条约会到达的测试消息
```

哪一步红就修哪一步；最后一条绿了说明真发出去了（QQ 会收到）。

### 5.3 「修复发送链路」修什么

自动做：切到中继 → 起 AstrBot 等就绪 → 清掉 SnowLuma 里残留的直连适配器 →
**重启中继（重新登记「可发送的 bot」）** → 真发一条验证；万一还是
`Failed to send message:`（空消息的 `ApiNotAvailable`）会再自愈重试一次。
约 20~40 秒，期间机器人不可用。

> 为什么要重连才能修：AstrBot（aiocqhttp）把「可发送的 bot」按 `X-Self-ID` 存在一张表里，
> 任意一条同账号连接断开时它都直接删这条登记（不校验归属）。所以**别让第二个客户端用
> 同一个 QQ 号去连 AstrBot 的反向 WS**（第三方 OneBot 面板、旧版本控制台的联调页探针都算），
> 它们一断开就会把中继那条真实连接的登记删掉 → 能收不能发。
> native 模式下「接进 AstrBot 的是 SnowLuma 自己那条连接」，所以那一模式的重启对象是 SnowLuma。

## 6. 两个网页面板的登录

「运行 → 面板登录」直接显示地址、用户名、**密码**：

- **复制密码**：一键进剪贴板
- **打开**：系统浏览器打开面板
- **一键登录**：桌面版开内嵌窗口，自动填用户名/密码并提交
- **重置密码**（仅 AstrBot）：AstrBot 初始口令只在首次启动打印一次，之后是散列不可逆。
  这里**按 AstrBot 自己的算法重设**一个 16 位强密码，并写回控制台配置（AstrBot 会自动重启一次）

> 忘了 AstrBot 面板密码就点「重置密码」，不用翻日志。

## 7. AstrBot 插件怎么用

1. 打开 AstrBot 面板（面板登录 → 一键登录）
2. 左侧「插件」→ 插件市场 / 上传本地插件（或把插件文件夹放到
   `runtime\astrbot\data\plugins\`）→ **启用**
3. **命令前缀默认是 `/`**。群里直接发 `/命令`，或按插件说明使用

已装插件示例（`astrbot_plugin_ccb_remake`）的可用命令：

```
/贴贴   /贴贴查询   /贴贴排行   /贴贴帮助
/棒棒列表   /恢复棒棒   /卸载棒棒
/查房   /受查   /好感度查询   /淫乱度查询   /主动排行
```

> 插件不生效时依次确认：① AstrBot 面板里插件是「已启用」；② 命令前缀对（默认 `/`）；
> ③ 用的是**中继模式**（native 模式下插件要回消息会撞上"能收不能发"）。
> 仍不行就点「双向自检」看发送链路。

| 机器人不回 | 联调页「双向自检」→「修复发送链路」 |

## 9. 升级

> 程序文件会换，**数据 / 安装 / 缓存不动**。完整说明见 [UPGRADE.md](UPGRADE.md)。

**应用内升级（推荐）**：配置页 →「升级控制台」→ 选新 zip → 检查 → 开始升级
（自动：备份程序文件 → 退出 → 覆盖 → 重启；失败自动回滚）

**手动覆盖**：先彻底退出（长按 `⏻` → 彻底退出），再解压新 zip 覆盖原目录。

## 11. 故障速查

| 现象 | 最可能的原因 | 处理 |
| --- | --- | --- |
| 机器人**能收到但不回**（私聊/群聊都不回） | native 模式下 bot 登记丢失 | 联调页「修复发送链路」→ 切中继 |
| 私聊能回、**群聊不回** | 同上（群聊走 `send_group_msg`） | 同上 |
| **插件不触发** | 前缀错 / 插件未启用 / 发送链路坏 | 见第 7 节 |
| `401 API Key 无效` | Key 空，或不是该服务商的 Key | 配置页「测试大模型连接」按提示修 |
| `端口 6185 已被占用` | 上次没退干净 | 配置页「清理残留进程」；重启时会自动先清理 |
| 一键登录密码错误 | AstrBot 口令是散列，控制台旧值失效 | 「面板登录 → 重置密码」 |
| 首启动慢 / 窗口"未响应" | 杀软扫描 + 首次解压 | 等 10 秒；日常用「收起窗口」而不是退出 |
| 关窗后还有进程 | 旧版本遗留 | 升级到当前版本；配置页「清理残留进程」 |
| 提示 `ApiNotAvailable` | AstrBot 侧没有可用 bot | 「修复发送链路」 |

## 12. 文件都在哪

| 内容 | Windows | Linux |
| --- | --- | --- |
| 配置、日志、备份 | `data\` | `~/.local/share/SnowLumaAstrBot/data/` |
| SnowLuma / AstrBot 安装 | `runtime\snowluma`、`runtime\astrbot` | `~/.local/share/SnowLumaAstrBot/runtime/{snowluma,astrbot}` |
| 安装包缓存 | `downloads\` | `~/.local/share/SnowLumaAstrBot/downloads/` |
| 升级日志 | `data\upgrade\upgrade.log` | `…/data/upgrade/upgrade.log` |
| QQ 多开分身 | `…\qq\clones\<名称>\` | `…/qq/clones/<名称>/home` |

**默认存储规划**：Windows 上程序会挑一块**非 C 盘**（剩余空间最大的本地固定盘）放在
`<那块盘>:\SnowLumaAstrBot\{data,runtime,downloads}`；机器只有一块盘时才用 C；
老用户升级会沿用原目录（不搬家）。Linux 上按 XDG 放在 `~/.local/share/SnowLumaAstrBot`
（即 `$XDG_DATA_HOME` 下）。想指定位置：环境变量 `SLAB_STORAGE_ROOT`（两个平台都支持）。

## 14. 出问题时要提供什么

1. 顶栏版本号（`v…`）
2. 「运行」页日志最后 30 行（或「终端」页导出）
3. 联调页「双向自检」的四行结果
4. 升级相关：`data\upgrade\upgrade.log`
